# Mining Bot 適応型先行・タイムアウト 実機確認手順

この文書は確認手順であり、実機で成功したという記録ではありません。

## 導入と比較

ゲームを終了して、レビュー済みビルドの通常JARを差し替える。sources JARは使わない。起動後にMixin適用失敗がないことをログで確認する。

最初は Mining Bot の Adaptive Aim Lead をOFFにし、同じ工具・同じ対象・同じ場所で通常採掘が続くことを確認する。黒曜石、下向きで水没していないLarge Amethyst Bud、Amethyst Blockは別々に確認する。

左クリック保持は対象選択とは独立している。旋回中に対象外へ照準が合ってもvanillaの採掘は許可される。タイムアウトは自動照準の対象を切り替える機能であり、対象外ブロックを保護する機能ではない。

## タイムアウト

1. Mining TimeoutをON、Timeout Durationを通常より短くし、設定値を保存できることを確認する。
2. その時間では壊せない対象へ採掘を開始する。別の可視・リーチ内候補があれば期限後にそちらへ旋回することを確認する。
3. 期限切れの対象が直ちに再選択されず、約5秒後に候補へ戻ることを確認する。
4. 別候補がない場合は待機することを確認する。Attack保持は継続するため、現在の照準位置への物理的な採掘停止は保証しない。
5. Mining TimeoutをOFFにして開始し直し、同じ秒数を超えてもタイムアウトによる切り替えが起きないことを確認する。
6. 確認後は通常の採掘所要時間より十分長い値（既定15秒）へ戻す。

## 適応型先行

1. Adaptive Aim LeadをON、Max Leadを既定200msにして開始する。
2. 通常採掘5件以上を観測するまで先行しないことを確認する。
3. 複数の候補がある状態で、少量の先行から試行が始まることを確認する。最大値は実際の先行量とは異なる。
4. サーバー由来の置換更新を確認できた先行試行は、通常採掘の所要時間サンプルへ混ざらないことを診断ログで確認する。
5. 先行して壊せなかった場合、確認期限後に先行量を0へ戻して再学習することを確認する。
6. 候補が1つだけの場合やMax Leadが0の場合は、先行による対象変更がないことを確認する。
7. OFFに戻して開始し直し、先行切り替えが止まることを確認する。

観測時間には往復通信やサーバー処理・更新配信の遅れが含まれる。サーバーtick数や自分の採掘だけによる破壊の証明としては扱わない。他プレイヤーの採掘が混ざりにくい場所で比較する。

## 終了・背景動作・効率

- Alt+Tab後も採掘が続き、復帰後に停止キーが効くこと。
- GUI、工具変更、死亡、切断で停止し、入力が残らないこと。
- 再接続や工具・対象変更後に、前の観測値や未確認対象が残らないこと。
- ON/OFFを同じ条件・同じ長さで複数回比較し、実際に壊れたブロック数とタイムアウト・先行失敗回数を確認する。視点が早く動くことだけで効率改善と判定しない。
- Sodium/Irisや背景tick抑制MODを使う場合はその構成でも別途確認する。
