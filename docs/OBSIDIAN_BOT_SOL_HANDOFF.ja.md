## 1. 依頼と役割

Minecraft MOD DragSimQolに、その場に立ったまま近くの黒曜石を掘り続ける独立機能 **Obsidian Bot** を実装する。既存のノード巡回採掘機能は **Route Walker** と呼ぶ。

ユーザーの確定要件:

- Obsidian Botは移動不要。近くの黒曜石を繰り返し掘る。
- 掘った黒曜石は岩盤へ変わり、一定時間後に黒曜石へ戻る。
- 視点移動は急な切替を避け、自然で滑らかにする。
- Route Walkerとは別の機能とする。
- 今後の実装担当はOpenCode/GLMではなく別タスクの5.6-sol。このタスクのCodexは設計・レビューを担当する。

引き継ぐ方針:

- 日本語で報告し、MOD内の表示・通知・ログは英語。
- 既存の未コミット変更を消さない。勝手にcommit/pushしない。
- 標準入力・標準の採掘処理を使用する。破壊パケットの独自送信、連打、採掘ディレイ短縮、OS入力注入を加えない。
- ビルド・単体テスト・実ゲーム検証を分けて報告する。
- 既存の要望を踏まえ、新BotもAlt+Tab中の継続を初期方針とする。ゲームのclient tickが進むことが成立条件。

## 3. 機能名と互換性

| 項目 | Route Walker | Obsidian Bot |
| --- | --- | --- |
| 動作 | ノード順に移動し、エンドストーンを採掘 | 移動せず、届く黒曜石を選んで採掘 |
| GUIカテゴリ | `Route Walker`（既存のMiningを改称） | `Obsidian Bot`（独立追加） |
| 初期トグル | Hを維持 | Jを暫定初期値、Controlsで変更可 |
| Controls表示 | `Toggle Route Walker` | `Toggle Obsidian Bot` |
| コマンド | `/routewalker ...` | `/obsidian ...` |
| ノード | 既存データを使用 | 不要 |

名前の変更で既存設定を失わない:

- `/routewalker` は既存 `/mining` と同じサブコマンド構造（例: `/routewalker route add`）。`/mining` はRoute Walkerへの互換aliasとして残す。新Botへ意味を転用しない。
- 既存KeyMappingの内部キー `key.dragsimmacro.mining_toggle` を維持し、英語表示だけ変更してControlsのユーザー割当を保つ。
- 既存ファイル `dragsimmacro-mining.json` と `dragsimmacro-mining-settings.json` の名前・ルート・保存済み速度を維持する。
- 内部のMining系クラス名は必要がなければ維持。全面renameで既存差分を膨らませない。
- GUI、通知、コマンドhelp/status、README等で利用者向けの呼称を揃える。古いログの意味やファイル名を黙って変更しない。

新Botの操作案:

```text
J                                     # 開始・停止（フォーカス中に受け付ける）
/obsidian stop
/obsidian status
/obsidian rotation speed <degreesPerSecond>
/obsidian rotation reset
```

GUIに独立した `Turn Speed` と状態表示を用意。新Botの設定ファイルは `config/dragsimmacro-obsidian.json` とし、Route Walkerの設定と分離。ON/OFF、現在ターゲット、待機リストを実行中の状態として扱い、起動後は常にOFF。

## 4. 推奨する採掘方式

**推奨: 到達可能で見える黒曜石を順番に掘り、すべてが岩盤等なら復活を待つ。**

効果: 待ち時間中に別の黒曜石を採掘できる。コスト・難易度: 中（候補探索・照準・採掘の状態管理）。リスク: 掘っている途中の頻繁な対象変更、壁越し判定、古い照準先を消費すると効率低下や誤採掘につながるため、対象固定と入力直前検証が必須。

次善: 最初に選んだ1ブロックだけを掘り、その復活を待つ。コスト・難易度: 低、視点移動が少ない。再生待ち中に他の黒曜石を掘れず、複数候補がある環境では効率が落ちる。近くの複数ブロックを掘る今回の初版には推奨方式を採用する。

### 候補と選択

- 探すのは実際の `Blocks.OBSIDIAN`。岩盤、泣く黒曜石、他ブロックは採掘対象にしない。
- 「近く」は現在のゲームモード・属性を含む標準のブロック到達距離以内。独自にリーチを延長しない。
- 目からブロック中心までの距離だけでなく、見えていて到達可能な面の照準点を評価する。壁や岩盤に遮られた黒曜石は候補にしない。
- 小さな周辺範囲を走査し、未ロードのchunkを読み込まない。探索範囲・候補数に上限を置く。暫定の再走査は5tickごと、現在ターゲットのブロック状態・射程・照準は採掘直前にも毎回確認する。
- 有効な採掘ターゲットを維持し、近い候補が追加されただけで切り替えない。状態変化・到達不能・遮蔽・採掘失敗の確定時だけ再選択する。
- 次の候補は短い視点移動を優先し、同程度なら距離と座標で決定する。毎tickランダムに選び直さない。
- 開始時にすべて岩盤でも「黒曜石がないからエラー停止」にせず、周辺に再出現する黒曜石を検出する待機状態に入れる。最初に見えた黒曜石の座標だけを再確認する方式では、新しく出現した候補を見落とす。

### 状態機械

```text
OFF -> SEARCHING -> AIMING -> MINING
           ^          |         |
           |          +---------+  対象の無効化・状態変化
           |
      WAITING_REGEN              全候補が不在・岩盤・到達不能

任意の稼働状態 -> OFF            手動停止・GUI・死亡・切断等
```

- `SEARCHING`: 小範囲の候補から選択。Attackは解除。
- `AIMING`: 対象ブロックの実際に見える照準点へyawとpitchを動かす。Attackは解除。
- `MINING`: 照準が対象ブロックに合っている間だけ標準Attackを保持。同じブロックを掘る間はターゲットと照準点を安定させる。
- 黒曜石→岩盤を観測したらAttackを解除し、当該座標を再生待ちとして記録して別候補へ。破壊音・腕振り・経過時間だけで成功と判定しない。
- 岩盤のほか空気や別ブロックへの変化もターゲット無効化として扱うが、黒曜石の採掘成功とは断定しない。
- `WAITING_REGEN`: Attack解除、最後の視点を維持して静かに待つ。実際のブロック状態が黒曜石に戻ったら、可視・射程を再確認して候補へ戻す。
- 復活時間は未知。固定秒数が経過しただけで岩盤を再び掘り始めない。復活待ちに短い強制停止期限を置かず、手動停止まで待てるようにする。
- 新Botの黒曜石にエンドストーンの「1tick採掘」を流用しない。採掘に時間がかかることは正常とし、固定の短いタイムアウトで次へ切り替え続けない。
- サーバーが破壊を拒否するケースは実際の標準破壊進捗等を根拠に限定的な再試行・失敗処理を設計する。採掘が遅いだけの状態と区別できないうちは、即失敗・高速対象切替にしない。

## 5. 視点・採掘入力

自然な見た目は、対象の固定、有限の旋回速度、yaw/pitchの描画補間で作る。初版はRoute Walkerと同様にリニア、初期120 deg/sを暫定値とし、新Botだけ別に調整可能とする。

- 新Botは真下固定ではない。目の現在位置と選んだ照準点からyaw/pitchを計算する。
- yawの最短角差とpitch差を組にして、両軸同時移動の角度変化も速度上限以内にする。各軸を独立して上限いっぱい動かすことで斜めだけ速くしない。
- yawは連続角、pitchは標準範囲内。角度を瞬時に対象へスナップせず、目標を越えない。
- MC非依存の2軸照準計算を用意し、tickで1回進める。描画は前tick・現在tickのsnapshotを補間して読むだけ。
- **既存カメラ補間はyaw専用かつ静的な単一snapshot。** 新Botではpitchの補間も必要。同じCameraメソッドへ競合するRedirectを増やさず、採掘用snapshotの所有者を明示して必要な軸を一つの統合経路へ渡す。
- OFF・切替・死亡・GUI時に所有者のsnapshotを無効化する。他機能を停止する操作で実行中の別所有者のsnapshotまで消さない。Route Walkerはyawの既存挙動と真下pitchを維持する。
- 26.2のCamera呼出し箇所とMixinのordinal/descriptorを再確認。カメラでの角度取得だけに限定し、描画からplayer角・移動・採掘入力を更新しない。
- MININGへの移行とAttack再適用直前に、vanillaが消費する実際の照準先が選択中の同じ黒曜石ブロックであること、射程・ツール・生存・GUI条件を確認する。単なる目標角との差だけを根拠にAttackを押さない。
- エンティティが照準を遮る、対象が岩盤へ変わる、手持ち変更が起きる場合は次の採掘消費前に解除する。既存のhotbar後hookだけで全ての順序が保証されると仮定しない。
- 別途計算したraycastと、vanillaが読む古いhitResultが食い違う実装を避ける。非フォーカス・低FPSでも照準更新が古くならないよう標準のpick経路と採掘消費の順を調べる。
- 照準点が岩盤から再生したらAttackを保持するだけで標準採掘が再開するか実機確認する。クリックqueue連打や直接破壊APIの併用で代用しない。
- 描画用に最大1tick遅れる視点と、実際の選択・入力の関係を確認する。yaw/pitchの補間は視覚用、射程や破壊条件は標準ゲーム状態に基づく。

## 6. 移動しないことと停止条件

- 新Bot自身はForward/Back/Left/Right/Sprint/Jump/Sneak/Useへ書き込まない。PathFollower、ApproachPlanner、warp、座標変更を呼ばない。
- ユーザーの移動入力も打ち消さない。開始位置を保持するための自動逆移動・テレポートを加えない。
- 開始時の位置・ワールド・プレイヤーを記録し、位置が1ブロック以上変わった場合は停止する暫定設計。ノックバックや手動移動で別の場所の採掘を勝手に続けない。微小な揺れで止まり続けないよう実機で調整する。
- 開始は黒曜石に対する標準の適正ツール所持時だけ。END_STONE用の判定を転用しない。通常の耐久値減少だけでは停止せず、スロット変更・別アイテム・ツール消失・不適正化では停止。
- 手動トグル、/obsidian stop、GUI（チャット含む）、死亡、切断、ワールド・dimension変更、player交換、クライアント終了で停止。GUIを閉じたり再接続しただけでは再開しない。
- フォーカス喪失だけでは停止しない。有効セッション中の自動pauseだけ抑止し、pauseOnLostFocusの保存設定を変えない。
- バックグラウンド中は物理入力を読まず、所要のAttackだけを再適用。停止では古いGLFW状態に邪魔されず所有入力を解除。フォーカス中の実物理押下は保持する。
- キーはフォーカス中に受け付け、H/J/Gを同じtickに押しても複数起動しない。停止はそのtickの自動操作消費前に反映。

## 7. 三機能の排他

実行者は `NONE / COMBAT / ROUTE_WALKER / OBSIDIAN_BOT` のいずれか一つ。WAITING_REGENもObsidian Botの有効セッションとして所有を続ける。

- 共通の開始・停止／入力所有調停を導入し、キー・GUI・既存コマンドすべての開始経路へ適用する。入口のUIだけで判断しない。
- 既に別機能が稼働中なら開始を英語の理由付きで拒否する。拒否のために現在の所有者の入力やカメラを解除しない。
- 停止済みのControllerが毎tick共有キーをfalseにし、稼働中のControllerを妨害しないようにする。所有入力のみ解除する。
- 過去の戦闘・巡回の残留入力／照準を整理してから新所有者を起動。整理で手持ちが変わる経路があれば新Botの開始検証をやり直す。
- Gだけでなく `/zealotdebug on` / toggle / GUI、ほかの実行経路も調べる。singleScan等の診断がターゲットを作るだけで戦闘処理を動かさないことも確認する。
- 戦闘設定・Route Walker設定をOFFへ永続化して排他を作らない。停止後に別機能を自動開始しない。

## 8. UI・通知と永続化

- GUIは既存の黒×紫、Oxanium、設定部品を使う。今回は新機能の設定・状態が分かればよく、既存画面全体を作り直さない。
- 状態例: `OFF`、`Searching`、`Aiming`、`Mining`、`Waiting for respawn`。
- 現在対象のブロック座標、有効候補数、速度、停止理由をstatusで確認可能にする。
- 通知例: `[DragSim] Obsidian Bot ON` / `[DragSim] Obsidian Bot OFF — held item changed` / `[DragSim] Cannot start — Route Walker is active`。
- 対象の切替や再生待ちを毎回チャットに流さない。通知は開始・停止・操作失敗中心。診断ログもtickごとの同期書込を避ける。
- Route Walkerのノード描画はShow Routeと現在ワールドの条件で表示し、Botの探索データをノードとして混ぜない。チャット中のノード表示と採掘停止の分離を保持する。
- 設定は検証付きで原子的に保存し、失敗を成功扱いしない。ターゲット・再生待ち座標はワールド退出時に破棄し、別ワールドへ持ち越さない。

## 9. 受入条件

単体・ロジックテスト:

- 複数の黒曜石を探索→照準→採掘→岩盤で切替。現在対象への固定、全岩盤で待機、後から出現した黒曜石の検出。
- 固定の復活タイマーだけでは採掘開始しない。長い正常採掘を短いtimeoutで切らない。
- 射程・遮蔽・エンティティ・岩盤・空気・泣く黒曜石・不適正ツール・持ち替え・古い照準のケース。
- yaw/pitch同時の速度制限・最短角・tick間補間・停止再開。renderゼロでも状態更新可能。
- 新Botが移動キー・Use・warpを操作しない。Attack所有の解除、非フォーカス時の物理入力非参照。
- すべての開始経路で三機能の排他。開始拒否・非所有者の停止・同tickのキー操作で実行者を壊さない。
- 旧/mining、KeyMapping内部キー、保存済みルート・設定・速度の維持。Obsidian設定を変えてもRoute Walkerが変わらない。

実ゲーム検証（テスト成功と分離）:

1. 適正ツールでその場に立ち、届く黒曜石が複数ある環境で開始。勝手に移動せず、視点が滑らかに移り、対象を途中で変えずに掘る。
2. 黒曜石→岩盤→再生を最低3サイクル確認。全岩盤ではAttackを解除して待ち、復活後に再開する。開始時に全岩盤の場合も確認。
3. 壁・エンティティで遮られた候補、射程境界、長い採掘時間、低FPSで誤採掘・対象振動がない。
4. Alt+Tab中も再生待ち→照準→採掘が継続。最小化は別確認。復帰後J、GUI、死亡・切断・持ち替え・移動で停止。
5. Route WalkerのH・リニア旋回・ノード描画・chat中描画・旧/mining・保存済みルートを回帰確認。Scytheの背景Holdと戦闘のカメラも確認。
6. 新しいCamera/input Mixinや共有化したhookの適用確認。クラッシュなく起動しただけで採掘成功とは報告しない。
