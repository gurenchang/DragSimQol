# Mining Bot: 左クリック連続保持と採掘中の微小な視点移動

ユーザーの追加要望: 掘り終わるたびに左クリックを離さず、Bot稼働中は保持を続ける。ターゲットに照準が着いた後も、そのブロック上で少し視点を動かしたい。

同じ5.6-solタスク・worktreeで既存未コミット変更を保持して実装する。日本語報告、MOD内は英語。commit/push/reset/cleanやlogs削除なし。

## 2026-09-19 追加指示: 設定対象外でも継続採掘

ユーザーは「設定対象以外に照準があっていても左クリック長押しで大丈夫です」と指定した。この節は、後述する旧仕様の「設定対象に実hitが一致する場合だけ採掘する」「対象不在中は破壊処理を待機する」という制限に優先する。

- Target Blockは自動照準、探索、再生判定、開始ツール適性を選ぶ設定として維持する。
- 有効セッション中はSEARCHING/AIMING/MINING/WAITING_REGENのすべてでAttackを保持し、設定対象外への照準、ターゲット未取得、岩盤への変化、旋回中を理由に標準continueAttackを抑止しない。通過する別ブロックの採掘が進む場合がある。
- セッション停止条件、vanillaの継続不可条件、実際のアイテム使用中・Piercing Weaponの禁止と限定cleanupは維持する。vanillaのfalseをtrueへ変更しない。
- 現行のstartAttack抑止による単一の継続採掘経路を維持し、エンティティへの自動攻撃やクリックqueue生成は追加しない。
- 自動照準対象のBlockState制約、形状・可視性・リーチ検査、Aim Driftは維持する。停止キー、GUI、死亡、切断、持ち替え等の所有入力解除も維持する。
- 英語UI説明を対象選択と連続保持の仕様に合わせる。対象外の採掘を許す挙動と既存停止条件を検証し、ビルドと実ゲーム確認は分けて報告する。

以下は変更前の引き継ぎ仕様。対象限定に関する記述だけは上記の追加指示に置き換わる。
## 入力と対象限定の両立

- 有効なMining BotセッションのSEARCHING/AIMING/MINING/WAITING_REGENで標準keyAttackを保持し続ける。対象消失・破壊完了・次対象への旋回・再生待ちだけを理由にsetDown(false)にしない。vanillaの入力リセットからの再適用も行う。
- OFF、J/コマンド停止、GUI、死亡、切断、ワールド/player変更、持ち替え、不適正ツール、規定距離の移動、対象種類変更、クライアント終了では従来どおり所有入力を解除。非フォーカスで物理入力を読まない、フォーカス中の実物理押下は停止時に維持する。
- 既存の対象限定要件を維持する。keyAttack保持の有無と、vanillaで採掘を進めてよいかの判定を分離する。旋回中の床/支持ブロック/非対象ブロック/エンティティを攻撃しない。
- 26.2のMinecraft.handleKeybinds/startAttack/continueAttackの順序と返り値を実バイトコードで確認する。必要最小限のクライアントMixinで、Bot稼働中だけ標準Attack処理へ渡す継続可否を検証する。無効な対象では標準continueAttack(false)相当の解除経路を通し、壊しかけの進捗を残さない。メソッドHEADを無条件cancelして標準stopDestroyBlockを飛ばす実装は避ける。
- 入力消費直前に、生存/GUI/ワールド/手持ち、到達距離、実hitResultの座標と選択対象の完全なBlockState、エンティティ遮蔽を検証する。古いhitResultで誤採掘しないよう標準pick更新の順も確認する。背景でpickが更新されないと継続不能なので、描画不要の標準pick経路が必要なら限定して使う。
- 独自パケット、OS入力注入、クリックqueue連打、標準採掘に重ねる直接破壊呼出し、採掘速度やディレイの短縮は追加しない。Scythe/Combat/Route Walkerの処理は稼働Bot以外では従来どおり。
- Mixin追加・変更は具体的に報告する。keyAttackは保持されても対象不在中は破壊処理を待機する設計であり、「岩盤も攻撃し続ける」「検知回避になる」とは説明しない。

## 小さな視点移動

- 同じターゲットへ照準が合った後、実VoxelShape内の可視・到達可能な小さな範囲で照準点を連続的に動かす。新しい対象へは既存のリニアTurn Speed、採掘中の変化はゆっくり小さくする。tickごとの独立ランダムjitterは使わない。
- 実装しやすい推奨案は、安定したアンカーの接平面で滑らかに変わる2軸オフセット。初期振幅は小さく（最大約0.03 block程度）、Budなど小さな形状ではさらに制限する。形状外、支持ブロック、遮蔽、射程外へ照準を動かさない。位相・振幅の変更、停止再開、対象切替でも急なスナップを防ぐ。
- 有効なドリフト点が取れない場合はアンカーを維持し、MINING/AIMINGの高速往復やターゲット再選択を引き起こさない。現在のターゲットブロック自体が無効になった場合は通常の次対象探索へ戻る。
- 変更は描画だけの見せかけにせず、tick側のplayer yaw/pitchと標準pickに一貫して反映する。renderは既存のyaw/pitch補間のみ。フォーカスや描画FPSに移動速度を依存させない。
- GUIのMining BotにAim Driftトグル（初期ON）と小さなDrift Amount調整を用意する。既存Turn Speedと別用途だと分かる英語表示にする。強さ0/OFFで安定照準へ戻る。既存設定移行・対象・速度を壊さず永続化する。新しいコマンドを追加するなら/miningbot配下と互換/obsidianに共通化する。

## 検証

- 掘削完了→別対象照準→待機→復活の遷移で、自動keyAttackにfalseを書かないこと。停止条件では所有分を解除、物理押下との共存、vanillaリセットへの再適用を確認。
- Attack継続の判定を、非対象/支持ブロック/エンティティ/旧hit/射程外/対象変化で検証。Bot OFFや他機能稼働には介入しない。
- ドリフトの有限性、速度/振幅上限、再現可能な時間更新、停止/切替、Bud小形状での範囲、OFF/0、設定保存復元を意味のある単位でテスト。実Minecraft形状/clipが必要な点は模倣ロジックの成功と区別する。
- 適切なテストと全体build、git diff --check。実ゲームの操作感・採掘継続・待機再生・背景動作・Mixin適用は未確認なら明示。生成JARの絶対パス・サイズ・SHA256を報告。
